# AI 学习平台需求文档

- 版本：v0.1
- 日期：2026-09-19
- 状态：产品需求草案，供后续设计、实现与试点验收使用；文中的新增能力尚未实现。
- 适用范围：以本仓库的决策树 Demo 为起点，定义下一阶段学习闭环与长期平台边界。

## 1. 产品目标

建设一个以学习任务和学生作品为中心的 AI 学习平台。学生通过适合知识特点的界面进行预测、实验、解释、编码和讨论；AI 根据可观察的学习证据理解其当前状态，在合适的时刻提供帮助，并逐步减少帮助，使学生能够独立解决新问题。

长期希望同一学习系统能够支持机器学习、深度学习、大模型应用和其他 AI 知识的学习。统一的是学习目标、能力证据、任务作品、工具上下文和帮助记录；不同场景可以采用不同工作空间，也允许接入外部学习工具。

下一阶段以决策树课程验证一个完整闭环：

> 先预测 → 动手实验 → 解释结果 → 换实例验证 → 完成可运行项目 → 在减少或撤掉 AI 帮助后独立解决新任务。

核心成功标准是学生的独立理解、判断与实践能力。课程完成率、页面停留时长、交互次数和 AI 对话量只作为过程指标。

## 2. 用户与使用场景

### 2.1 首轮试点对象

以下为本版需求的工作假设，不代表平台长期只服务这类学生：

- 主用户：具备基础 Python 阅读和修改能力、正在入门机器学习的学习者。
- 次用户：需要设计课程、检查学习证据和定位教学问题的课程作者或教师。
- 首轮使用桌面或笔记本浏览器；完整手机学习体验暂不作为交付目标。
- Python 前置能力不足的学生可以完成概念实验，项目入口应明确前置要求并提供补充学习路径，避免把编程困难直接判断为概念不理解。

### 2.2 关键场景

| 场景 | 学生需要完成的事 | 平台应提供的支持 |
|---|---|---|
| 建立概念 | 读懂一棵树，解释一刀分裂的效果 | 可操作对象、必要讲解、预测与反馈 |
| 比较与探索 | 改变深度或剪枝参数，理解结果变化 | 实验对照、过程记录、保留自由尝试空间 |
| 解决困难 | 发现自己的预测与结果不一致 | 与当前对象关联的分级帮助、针对性补练 |
| 独立验证 | 在没有见过的实例上作判断 | 新任务、明确的帮助状态、独立能力证据 |
| 完成项目 | 编写并运行代码，比较模型，解释选择 | 数据、运行环境、实验记录、作品提交 |
| 继续学习 | 回到上次任务并知道下一步 | 草稿恢复、能力证据摘要、可解释的推荐 |

## 3. 当前基础与缺口

本节描述当前仓库实现，后续需求描述目标状态，两者不得混用。

| 方面 | 当前已实现 | 下一阶段缺口 |
|---|---|---|
| 课程与交互 | 一门决策树课程，CART 主线与 ID3/C4.5 进阶共 10 个概念，共用学习引擎 | 尚未验证不同学科任务的复用能力 |
| 学习者模型 | 按概念记录答题、误解、讲解层次，使用固定参数 BKT 估计掌握度 | 提示后答对、重复答对与独立答对尚未充分区分；估计值未经真实学生数据校准 |
| 行为采证 | 实验、预测、选择题、自由回答可以产生证据 | 部分探索操作直接被判为错误或误解；一次答对可清除本概念的全部误解 |
| 教学策略 | 根据误解、作答情况选择补讲、实验与练习 | 新实例主要作为掌握度不足时的补练，尚非所有人的必要验证 |
| AI 帮助 | 读取当前实验、题目、草稿，支持错误反馈与轻提醒 | 帮助主要为侧栏文字；自由问答请求未携带前序对话历史 |
| 代码与项目 | 剪枝实验显示与参数同步的代码片段 | 代码不能编辑运行，缺少陌生数据上的独立项目 |
| 持久化 | 本机浏览器保存课程进度 | 缺少带版本的完整证据与作品恢复、导出机制 |
| 页面组织 | 概念导航、中央学习区、右侧 AI 的三栏结构 | 任务与实验可进一步前置，辅助面板与可访问性需要改进 |

应保留的基础包括真实计算、先判断再反馈、课程与引擎分离、可解释教学策略，以及学生可以选择继续独立探索的机制。

## 4. 范围与优先级

- **P0：决策树学习闭环试点必须具备。** 可信采证、能力证据展示、必要的新实例验证、可运行结课项目、可控的情境帮助、恢复与验收。
- **P1：闭环完成后验证和扩展。** 更丰富的对象级帮助、延迟复测、对照研究、差异明显的第二种学习任务、课程制作辅助。
- **P2：长期建设。** 多课程能力关联、外部工具接入、更多 AI 学习工作空间。

本轮不包含完整课程商城、支付、学校管理、复杂账号体系、通用云端 IDE、全部 AI 课程制作和未经检查的课程自动发布。首轮保留单机学习方式，提供试点所需的记录导出即可。

## 5. 学习体验与教学规则

### 5.1 概念学习流程

1. 进入概念后，先看到本步需要解决的问题、完成标准与当前建议。
2. 在揭晓结果之前提交预测或选择，并在需要时说明理由。
3. 操作实验，观察与预测有关的结果；允许自由试错和比较。
4. 解释预测与实际结果的差异，必要时获得提示或补充讲解。
5. 完成陌生实例验证，形成有来源的能力证据。
6. 决定继续下一步、补练或自由浏览其他内容。

### 5.2 表现形式的选择原则

每项活动必须同时定义学习目标、学生动作、可观察结果与验收证据。文本、视频、动画、实验、代码和讨论都可以使用，具体形式由任务决定。

| 学习目标 | 主要形式 | 关键证据 |
|---|---|---|
| 理解分裂 | 阈值、样本分组与纯度联动 | 在新样本上选择分裂并解释依据 |
| 理解泛化 | 参数、树结构与训练/验证曲线联动 | 能解释训练表现与验证表现分歧 |
| 理解稳定性 | 不同采样下的树与预测对照 | 能解释数据扰动造成的变化及局限 |
| 掌握实现 | 可编辑运行的代码和实验结果 | 可复现结果、处理错误、完成新任务 |
| 判断适用性 | 案例比较与解释 | 有依据地选择方案，并指出适用边界 |

### 5.3 帮助逐步减少

引导学习可以给出观察方向、反例和步骤提示。独立验证开始前说明允许使用的资源。学生仍可退出验证并请求教学帮助，但该次尝试应转为辅助练习；之后通过另一个未见任务重新验证独立能力。

不要求每个概念机械套用完全相同的页面顺序。课程作者可以组合活动，但不能用浏览、点击或重复已揭晓的答案替代必要的理解证据。

## 6. 功能需求

### FR-01 学习证据采集与解释（P0）

- 分开记录探索行为、明确判断、解释、代码运行、作品提交和接受帮助。
- 自由调参、重复比较、停留和打开讲解只记录活动，不能直接增减理解状态或判定误解。
- 仅在学生提交预测、声明采用某方案或回答诊断问题后，对相应能力作判断。
- 记录任务实例、尝试轮次、是否已见结果或解析、帮助类型与等级；同一实例的重试不得当作独立新证据累计。
- 误解状态至少区分待核实、已有证据支持、已通过针对性验证解决。选中错误选项可以形成待核实线索，不能自动证明学生持有选项隐含的全部理由。
- 部分正确保留其已命中与缺失的评分项。网络错误、运行环境故障和批改失败记录为未评定，不更新能力结论。

**验收：** 学生故意过度剪枝观察后果，不被记录为“相信剪枝越狠越好”；学生答对其他问题，不会清除无关误解；同题排除选项后答对与新题首次独立答对可以明确区分；批改失败不记作答错。

### FR-02 能力状态与推荐说明（P0）

- 学生侧主要展示具体能力及证据，如“能读懂树的预测路径”“能在新数据上选择深度”。
- 能力状态至少支持：尚未验证、学习中、已通过独立同类验证、已通过新情境验证；可另显示待复习提示。
- “已通过独立同类验证”要求该能力的必要评分项在未见同类实例上、按规定资源条件独立通过；“已通过新情境验证”还要求通过课程标明的新情境任务。没有配置相应验证活动的能力，不能授予该状态。
- 每个结论可以展开查看来源任务、日期、帮助情况、已完成与尚缺少的评分项。
- 内部可继续使用 BKT 辅助推荐，但不把未经校准的百分比呈现为真实理解概率，也不单独依靠分数授予能力状态。
- 推荐下一步时说明针对哪项能力、依据什么证据，以及本次活动要验证什么。
- 内容浏览默认开放，前置关系用于建议学习顺序；能力通过标记与浏览权限分别处理，消除“显示未解锁但仍可进入”的含混状态。
- 旧版进度迁移保留为历史学习记录，缺少帮助和独立验证信息时不得直接转换为新标准下的独立能力证明。

**验收：** 从能力卡片能追溯具体尝试；辅助后完成不会显示为独立通过；进入建议之外的章节不会自动获得能力标记；旧存档不被静默删除或提升结论。

### FR-03 必经的新实例验证（P0）

- 决策树主线的读树、分裂选择、过拟合判断和剪枝取舍均提供至少一个未见实例验证；不能只给进度落后的学生使用。
- 新实例应改变与能力相关的条件。仅交换选项顺序或替换无关名称不算新实例。
- 变式应防止固定口诀通关，例如优胜分裂特征发生变化、加深后验证效果可能改善也可能变差。
- 任务版本、数据、种子、答案计算与评分规则可复现；训练练习与独立验证的实例不复用。
- 作答前不得通过颜色、标签、排序、默认选中项或 AI 提示暴露正确答案。需要读图的题目可提供完整曲线，但不能额外突出正确位置。
- 独立验证期间首次需要教学提示时，说明该次尝试将转为辅助练习，保留草稿，允许学生继续选择。

**验收：** 全对路径也会进入新实例验证；系统不会向同一学习者重复发放已揭晓实例作为独立验证；曲线题作答前各候选位置的提示样式一致；请求帮助后的作答有辅助标记。

### FR-04 决策树可运行结课项目（P0）

提供一个围绕陌生分类数据的完整项目。首轮使用作者准备、带版本的数据包与并行变式，避免把任意数据接入能力纳入本轮范围。

学生需完成：

1. 识别特征与目标，说明训练、验证数据的职责，并实施合理的数据划分。
2. 运行一个基线，确认数据处理、训练和评估能够完整执行。
3. 比较至少三个有效配置，其中包含基线和对复杂度参数的改变，记录训练与验证指标及树的规模。
4. 选择一个模型，以实验记录解释取舍；不能只凭训练准确率判断模型好坏。
5. 提交代码、数据划分记录、实验结果与文字结论，随后完成一个新数据变式上的独立验证。

平台要求：

- 提供可编辑、可运行、可停止的 Python 工作区，支持本项目使用的 `DecisionTreeClassifier`，显示真实运行输出与错误。
- 提供环境和数据加载脚手架，逐步减少对数据划分、配置比较和结论的代做。
- 每次运行关联准确的代码版本、数据版本、划分与随机种子。参数改变后，旧结果必须标记为对应旧版本。
- 实际执行结果是成绩与反馈的依据；当前 JavaScript 实验与 Python 执行若存在差异，应标明各自来源，不用实验室数字替代代码运行结果。
- 任务接受多个合理方案，评分依据数据使用、实验设计、代码正确性和解释质量，不要求匹配作者唯一参数或达到单一准确率门槛。
- 独立验证沿用已学的能力，但更换数据实例或任务条件；仅重新执行原作品不足以通过。

**验收：** 在新会话中能从保存的代码与任务包复现结果；可以修复一次实际代码错误后重跑；辅助完成的项目与新变式独立通过分别显示；结课结果能查看作品及逐项评分依据。

### FR-05 情境感知与分级帮助（P0）

- AI 读取当前目标、活动、已展示结果、选中对象、相关代码版本、错误信息、作答草稿，以及与当前任务有关的能力和帮助记录。
- 当前任务内的追问保留必要对话上下文，能够处理“为什么刚才那个结果会变”等指代；切换任务时避免混入过期实验状态。
- 帮助依次支持：指出观察对象、提出思考问题、提供对比例子、给出部分步骤。展示完整解法属于辅助学习，不计为独立验证。
- 停留或反复调参只触发可忽略的邀请，不直接宣称学生卡住或存在误解。学生可以选择“我在比较”“继续自己想”或“需要提示”。
- 明确提交错误后，先显示可验证的结果差异，再按活动规则提供解释或进一步诊断。
- 学生能关闭主动教学提醒并随时恢复；关闭后仍可主动提问。界面的必要运行状态和错误提示继续显示。
- AI 不自动修改学生答案、最终模型选择或已提交作品。
- 停留阈值、提醒间隔和提示策略可配置并记录版本；现有阈值只作为初始设置，不视为已验证的最佳教学时机。

**验收：** AI 能区分同一任务前后两次结果；后台页面不触发停留提醒；关闭主动提醒后不重复催促；旧请求迟到不会覆盖新任务反馈；所有已交付帮助均能关联到受影响的尝试。

### FR-06 学习界面与对象级反馈（P0/P1）

**P0：**

- 保留概念导航与主工作区，在页面上方明确本步任务和完成标准，使主要实验更早进入视野。
- 讲解按需展开；AI 面板可收起和重新打开，保留对话与任务状态。
- 反馈优先靠近发生判断的图、树或题目，提供“查看相关对象”入口，避免学生反复在长页面与侧栏之间寻找对应关系。
- 运行、批改、未保存和未评定状态明确可见；失败后保留输入并允许重试。

**P1：**

- 高亮相关树节点、曲线区段或代码位置；并排对比两次已记录实验。
- AI 可建议切换视图或打开对照，但由学生发起会改变实验配置的动作。
- 对象级动作仅使用工作区登记的操作和对象标识，不能用任意生成代码直接控制页面。

**验收：** 收起 AI 后仍能完成任务并查看反馈；反馈定位到本次判断使用的对象与结果版本；作答前定位不会泄露正确答案；恢复面板不丢失消息。

### FR-07 状态恢复、作品保存与试点导出（P0）

- 保存当前任务实例、草稿、代码、已完成运行、帮助暴露、评分与能力证据；刷新或暂时离开后可恢复。
- 存储失败时明确提示未保存，提供下载当前作品或重试入口，不能仍显示已保存。
- 刷新和切换页面不能清除提示记录，使辅助尝试重新成为独立尝试。
- 支持导出一个包含任务版本、证据、帮助记录、作品和评分的试点包，供教师检查；无须建设完整教师后台。
- 任务与课程升级保留历史记录。结构不兼容时说明哪些内容可以恢复、哪些需要重新验证。
- 仅记录本学习工作区中的相关活动。“平台内未使用教学帮助”不等于已证明学生未使用任何外部帮助，研究报告需明确观测范围。

**验收：** 刷新后恢复原任务实例与代码；独立性标记不丢失；导出的作品可与其实际运行、评分对应；存储失败不会静默丢稿或误报保存成功。

### FR-08 可信运行与评分（P0）

- 数值、树结构、预测结果和代码执行状态来自真实计算，保留现有算法测试与内容核对基础。
- 自由回答按明确评分项反馈。LLM 判定不确定、响应无效或重试仍失败时，保留为待核实或未评定，允许重试；试点教师可以查看原回答与评分依据。
- 代码评分拆分为能否运行、数据使用是否合理、实验比较是否完整、结果是否一致、解释是否成立。任何一项通过不能替代其他必要项。
- 生成题无法重建、答案冲突或验证失败时，使用预验证的备用新实例，或明确显示当前无法验证；不能跳过验证并授予通过。
- 运行与评分请求有明确的运行中、成功、失败、超时、已取消状态，学生可以停止；重复请求不重复累计证据。
- 代码运行环境与平台服务隔离，不接触平台密钥或其他学习者状态；限制资源和执行时长，运行故障不得导致整个学习页面失效。
- AI 服务不可用时，本地实验、代码编辑、代码运行和作品保存仍可使用；依赖语义批改的能力项保持待评定。

**验收：** 超时可以停止并再次运行；无效评分不导致自动通关或扣分；缺少有效数据划分、只有训练指标或代码与结果不一致时，项目对应评分项不通过；相同提交只生成一次有效评分记录。

### FR-09 课程任务协议与作者支持（P0 基础，P1 扩展）

**P0：** 在现有课程、实验与练习注册机制上，补充活动类型、目标能力、任务版本、帮助规则、评分项和作品要求。领域算法留在实验或任务实现中，通用引擎负责事件、状态、推荐与帮助调度。

**P1：** Coding Agent 辅助课程作者创建任务脚手架、数据变式、反例和验证用例。每个产物保留来源与版本，通过内容核查、执行检查、评分检查和人工试学后，才能进入正式学习路径。

优先提炼任务契约与真正复用的组件；新任务允许有自己的可视化和操作方式，不强制填入决策树页面结构。首轮用结构化配置与注册接口满足作者需求，不建设完整可视化课程编辑器。

**验收：** 一个课程任务可以声明学习目标、上下文、操作、证据和评分要求；缺少必要字段或答案验证失败时不能进入独立验证路径；新增领域任务不要求在通用采证逻辑中写入具体学科判断。

## 7. 数据与工作区契约

本节定义产品所需的信息，不限定最终数据库或接口字段名称。首轮可继续本机持久化，但需要版本管理与导出。

| 对象 | 必需信息 | 用途 |
|---|---|---|
| 学习会话 | 本地学习者标识、会话标识、课程与版本、当前任务 | 恢复与归属 |
| 任务实例 | 任务及版本、能力目标、活动类型、数据版本、种子或实例摘要、评分规则版本 | 复现及判断是否为未见实例 |
| 尝试 | 尝试标识、任务实例、开始与提交时间、首次或重试、提交版本 | 防止重复计分，追踪过程 |
| 行为事件 | 唯一事件标识、时间、对象、动作、关联的任务/尝试/结果版本 | 描述探索，不隐含对错 |
| 帮助暴露 | 来源、内容或引用、等级、展示时间、影响的尝试、是否已见答案 | 区分辅助与独立完成 |
| 运行记录 | 运行标识、代码与依赖版本、数据划分、随机种子、结果、错误、状态 | 复现作品与生成可信反馈 |
| 评分证据 | 来源尝试、评分项、结论、理由、评分方式与版本、是否需核实 | 支持能力结论与复核 |
| 能力与误解 | 能力标识、当前状态、支持/反对证据、仍需验证的项 | 解释推荐，避免过度推断 |
| 学生作品 | 代码、结果与实验记录、文字结论、任务与依赖信息 | 作品保存、提交与导出 |

需要满足以下规则：

1. 事件写入与评分具有幂等性；刷新、重试或重复响应不重复提升能力状态。
2. 同一任务的作答、帮助、运行与评分可以串联；帮助发生后不得覆盖或丢弃其来源。
3. 无正确性结论的事件保留为观察值，不按 `false` 或默认权重进入对错更新。
4. 原始评分与后续复核结果分别保存，能力状态能够说明使用了哪一版结论。
5. 请求携带上下文版本；迟到的 AI 回复或运行结果只能归入原版本，不能冒充当前页面结果。
6. 隐藏答案、评分专用材料与已经向学生展示的事实分开管理；教学提示不能直接透传隐藏材料。
7. 数字来源检查继续保留，同时检查反馈是否正确解释这些数字；数字可溯源本身不足以证明解释正确。

各类工作区至少提供：当前任务与选中对象、已经显示的结果、可用操作、行为事件、明确提交和作品引用。后续可以用同一契约接入实验、代码、论文与项目空间。

## 8. 体验与质量要求

| 方面 | 首轮要求 | 验收方式 |
|---|---|---|
| 可读性 | 关键说明、状态、图例清晰可读，颜色以外还有文字或形状区分 | 检查主要页面与错误/禁用状态 |
| 键盘使用 | 导航、作答、滑块、代码操作及需要点击的图形提供键盘路径和可见焦点 | 仅用键盘完成一条概念验证路径 |
| 桌面布局 | 在 1280×720 与 1440×900 下能完成核心任务；面板可收起 | 走查任务、实验、反馈、项目页面 |
| 页面缩放 | 200% 缩放时关键内容不丢失；图表可提供滚动或等价数据视图 | 验证读数、作答与提交操作 |
| 操作反馈 | 普通交互不等待 LLM；异步操作及时显示状态，避免无提示等待 | 检查运行、批改、取消、断网与重试 |
| 结果一致性 | 显示数字与其运行/算法版本一致，旧结果可识别 | 对照固定任务包与运行记录 |
| 记录完整性 | 无声丢稿、重复计分、旧回答覆盖新任务均属于阻断问题 | 刷新、切换、重试与失败恢复测试 |

运行时间上限、内存上限及性能基线在运行环境技术验证时确定，作为试点配置记录。不能在尚未测量前承诺统一的模型响应时长，也不能仅凭截图宣称完整可访问性达标。

## 9. 试点与学习效果评价

### 9.1 功能通过与教学有效分别验收

功能验收证明系统按需求运行。小规模试学用于发现任务不清楚、操作受阻、误判和打断；不能据此声称平台已经提高学习效果。

效果评价关注以下指标：

| 指标 | 定义或观察方法 | 阶段 |
|---|---|---|
| 独立新题表现 | 未见实例、无平台教学帮助条件下的评分；同时报告退出或转为辅助的比例 | P0 记录，P1 比较 |
| 独立项目质量 | 实际执行、数据使用、实验设计和解释的分项评分 | P0 |
| 辅助依赖 | 辅助完成后，在新实例独立验证中的表现变化 | P0 记录，P1 分析 |
| 帮助的作用 | 记录触发原因、是否接受、后续表现及学生反馈的打断感 | P0 记录，P1 分析 |
| 保持与延后迁移 | 间隔后在未见任务上复测，预先固定间隔和评分规则 | P1 |
| 工程可用性 | 任务完成障碍、运行/批改失败、恢复成功情况、记录缺失 | P0 |
| 内容制作成本 | 新任务制作、核查、试学与修订所需人工投入 | P1 |

不把“自主请求帮助者”与“不请求帮助者”的成绩差直接解释为帮助的因果效果；也不只统计坚持完成独立验证的人而遗漏退出者。

### 9.2 后续对照方案（P1）

在内容、目标、学习时间与评价任务尽量一致的条件下，可比较：

- 对话式教学。
- 交互实验与固定教学反馈。
- 交互实验与情境 AI 帮助。

预先确定分组方式、前测、主评价指标、评分规则、延后复测安排，以及 AI 和课程版本。组间同时变化的因素应明确记录。样本量按预期效应与研究设计确定；首轮可用性试点不承担统计证明任务。

正式判断优先看撤掉 AI 后的新任务表现与延后保持，辅以过程体验、成本和失败情况。数值目标在收集基线后确定，不能把需求文档中的预期写成已获得的结果。

## 10. 交付阶段与完成条件

| 阶段 | 工作范围 | 完成条件 |
|---|---|---|
| M1：可信采证与新实例验证 | FR-01/02/03、基础帮助规则、旧档迁移、现有页面调整 | 自由探索不再被当作概念错误；全对路径仍经历新实例；能力结论可追溯；原课程可正常学习 |
| M2：决策树完整学习闭环 | 可运行项目、情境帮助、恢复/导出、评分与异常处理，完成全部 P0 | 完成一条引导学习、项目提交、新变式独立验证的真实浏览器流程，并覆盖辅助与失败恢复路径 |
| M3：试点评估与差异任务验证 | 试学修订、P1 对象级帮助、延后评价，以及差异明显的第二任务原型 | 有可复核试点记录；说明学习结果与证据局限；明确哪些能力真正复用、哪些仍需专门开发 |

M2 之前先进行运行环境技术验证：确认项目依赖能执行、代码隔离、资源限制、取消、版本保存与结果复现。浏览器内运行或隔离的服务端运行均可满足需求，具体选择以验证结果为准。若运行环境尚未完成，FR-04 不能用代码展示视图替代验收。

以下场景作为 M2 的必测验收路径：

| 编号 | 场景 | 预期结果 |
|---|---|---|
| AC-01 | 自由调参导致模型变差，随后恢复 | 仅形成探索记录，不扣理解状态、不新增确定误解 |
| AC-02 | 提交带明确错误理由的判断 | 更新对应评分项，提出针对该理由的诊断或补练 |
| AC-03 | 同一概念的另一个问题答对 | 不自动消除与该问题无关的误解 |
| AC-04 | 作者题首次全部答对且内部估计很高 | 仍进入必要的未见实例验证 |
| AC-05 | 看过提示后答对，刷新并重答 | 保留辅助与重试记录，不转为独立通过 |
| AC-06 | 曲线判断尚未提交 | 无额外正确答案高亮或等价泄露 |
| AC-07 | 修改项目代码或参数后运行 | 显示本次真实输出，能定位代码与数据版本 |
| AC-08 | 只提交训练分数，没有有效数据划分 | 对应项目评分项不通过，并说明原因 |
| AC-09 | AI 失联、运行超时或评分响应无效 | 保留草稿与作品，状态为失败或未评定，不重复计分 |
| AC-10 | 请求 AI 后立即切换任务 | 旧响应不出现在新任务的反馈位置 |
| AC-11 | 关闭主动提醒后继续独立比较 | 不再主动催促，主动提问仍可使用 |
| AC-12 | 从旧版已掌握存档升级 | 保留历史进度，独立验证信息缺失的能力显示待验证 |
| AC-13 | 完成辅助项目后进入新数据独立验证 | 两类结果分开记录，项目可从导出包复现 |
| AC-14 | 仅用键盘并收起 AI 面板 | 能完成概念任务、作答、查看反馈和继续导航 |

测试应覆盖以上关键行为和现有算法/内容校验；批改语义质量通过固定评分样例与人工复核检查。既有单元测试或端到端测试通过，不能替代新增需求验收。

## 11. 长期平台边界

### 11.1 统一的能力

持续积累学生的目标、任务、作品、理解证据和帮助历史，使 AI 在新的学习场景中能够获得相关上下文。能力关联应有明确证据，不能仅因两个课程使用相似术语就自动互认掌握状态。

工作空间可以包含概念实验、代码与 Notebook、项目调试、论文阅读与批注、方案讨论。外部工具接入应提供任务、结果与作品的显式关联，不以“必须把所有内容搬入同一页面”为前提。

### 11.2 用差异明显的任务验证复用

M3 默认候选为“调试一个训练失败的神经网络”的小型任务，检验代码运行、错误诊断、多步实验与多种合理解法。若试点对象更适合大模型应用，可替换为范围受控的 RAG 评估任务。

该阶段不要求编写一门完整新课。重点检查新增任务能否复用采证、帮助、作品与恢复机制，以及需要多少领域专门开发。决策树两章共用引擎只能证明当前范围内的复用，不能据此认定所有 AI 学习场景均已覆盖。

### 11.3 Coding Agent 的角色

- 面向作者：辅助制作实验、脚手架、变式与验证用例，保留作者对目标和评分标准的控制。
- 面向学生：读取工作区过程，定位问题、组织比较和提供渐进帮助，保留学生对方案与作品的决定权。
- 面向平台：降低可信教学活动的制作与维护成本；该价值需要通过新增任务的实际投入和修订量验证。
