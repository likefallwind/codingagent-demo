# LearnAI

一个以**学习任务和学生作品**为中心的 AI 学习平台原型，按 [需求文档](doc/AI学习平台需求文档.md) 的 M1 + M2（全部 P0）实现。现在用决策树课程验证一个完整闭环：

> 先预测 → 动手实验 → 解释结果 → 换实例验证 → 完成可运行项目 → 在撤掉 AI 帮助后独立解决新任务。

和聊天式教学的区别：

- **证据分开记。** 探索（拖滑块、打开讲解）只是行为事件；只有提交的判断才评分；每一次帮助都记在它影响到的那次作答上。
- **能力要独立验证。** 课程题做得再好，也要在**没见过的新题**上、不用帮助、第一次就答对，才标为「已通过独立同类验证」；结课项目的新数据变式独立通过，才标为「已通过新情境验证」。内部的掌握度估计只用来推荐练习，从不显示成百分比。
- **项目跑真代码。** 结课项目在浏览器里隔离的 Python（Pyodide + scikit-learn）里真实运行，按运行记录逐项评分。
- **AI 老师看得见、说得少、记得住。** 它看得到实验、题目、代码和之前的结果；主动开口只限几种确定性情况，而且只「邀请」不「断言」；给出的每条帮助都有等级、有记录。

| 章节 | 内容 | 数据与算法 |
|---|---|---|
| 主线：一棵树的一生 | 7 步：读树 → 纯度 → 贪心建树 → 深度 → 过拟合 → 剪枝 → 不稳定 | 16 个水果样本 + 同一果园多批合成数据；CART（二叉阈值分裂、基尼） |
| 进阶：多值特征的陷阱 | 3 步：熵与信息增益 → 行号陷阱 → 增益率的边界 | 14 天打网球数据；ID3 / C4.5 |
| 结课项目 | 陌生数据上的完整建模：主项目（可用 AI）+ 新数据变式（独立验证） | 3 个带版本的数据包；真实 scikit-learn |

## 运行

需要 **Node 18+**。首次运行会自动安装依赖。

```bash
cp .env.example .env              # 可选：填入 MINIMAX_API_KEY
./start.sh                        # 打开 http://localhost:5173
```

| 命令 | 作用 |
|---|---|
| `./start.sh` | 开发模式：Vite :5173 + API :8787，改代码自动重载。**日常用这个。** |
| `./start.sh prod` | 先构建，再由单个进程在 :8787 托管前后端。 |
| `./start.sh test` | 单元测试（`npm test`）。 |
| `./start.sh e2e` | 真浏览器验收：整门课走两遍 + AC-01～AC-14 逐条。默认用**离线 AI 替身**，不需要 key，约 5 分钟。`E2E_REAL_LLM=1` 改用真实模型。 |
| `./start.sh stop` | 停掉残留进程。 |

**没有 API key 也能用。** 实验、对错判定、独立验证、代码运行、作品保存都在本地完成；依赖语义批改的部分（简答题、项目的文字解释）显示「未评定」，可以稍后重试，不会被算对或算错。

**离线 AI 替身：** `LEARNAI_FAKE_LLM=1 npm run server` 让 AI 老师由确定性的替身回答（`server/fakeTutor.js`），用于测试和离线演示。它只检验流程，不代表真实模型的批改质量。

**结课项目的 Python 运行环境：** 试点前跑一次 `npm run pyodide`，把 Pyodide 0.27.7 和项目用到的包（numpy、pandas、scikit-learn 及其依赖，约 49 MB，逐个核对 sha256）存到 `public/pyodide/`，由本站直接提供，课堂上不依赖外网。没存的话会退回从 cdn.jsdelivr.net 下载——实测 CDN 慢的时候首次加载要好几分钟。

## 学习闭环

### 一步里发生什么

页面最上方是**本步任务、完成标准和当前建议**（建议会说明它针对哪项能力、依据什么证据、这次活动检验什么）。下面依次是按需展开的讲解、实验、题目和独立验证：

1. **讲解**：直觉常开，例子和形式化按需展开。
2. **实验**：先预测再揭晓。提交的判断（如「我觉得是这个叶子」「采用这组剪枝设置」）评分；随便调参只记为探索。
3. **课程题**：选择题本地判分；简答题按作者写的**评分要点**逐条批改。选项顺序按题目固定打乱——作者写的正确答案原本几乎都在 A。
4. **独立验证**：两道由算法生成、学生**没见过**的新题。开始前说明可用资源；提交前不显示任何对错；提交后显示答案，这几道题以后不会再出现。**全对的学生也要做**（AC-04）。
5. 没通过 → 先练一道新题 → 换一组新题重新验证。

浏览全程开放：前置关系只作为「建议先学」出现，打开某一步不会改变任何记录。

### 能力状态

| 状态 | 条件 |
|---|---|
| 尚未验证 | 没有作答记录 |
| 学习中 | 有引导学习的记录，但没有独立验证 |
| 已通过独立同类验证 | 本步的验证题：没见过的实例、第一次作答、没用帮助、全部答对、当前任务版本 |
| 已通过新情境验证 | 上一条 + 结课项目的新数据变式独立通过（适用于「区分训练/验证」「选深度」「剪枝取舍」三项） |

「树的不稳定」一步没有配置验证题，所以它的能力**不会**被标成已验证——页面会明说。每个结论都能在「能力档案」里展开：来源任务、时间、帮助情况、命中和缺少的评分要点。

### 证据规则（FR-01）

- **尝试（attempt）**：一个学生对一个任务实例的一次作答。刷新或离开再回来恢复的是同一个尝试，帮助标记不会丢。
- **同一实例的重试**记录但不算新证据；看过答案的题再做，也不算独立。
- **帮助**（提示、问答、答错后的解释、关键时刻的提醒）一旦出现就记在它影响的尝试上，这次尝试从此是「辅助」。
- **误解三态**：选错选项只形成**待核实的线索**；学生自己写出这个理由（批改有把握时），或同一线索在不同题上再次出现，才是**已有证据支持**；只有在**另一道**针对它的题上第一次、不借帮助答对，才算**已澄清**。答对一道无关的题不会清除任何误解（AC-03）。
- **未评定**：网络故障、AI 批改失败或不确定（置信度低于 0.5 记为「待核实」）都不改变任何结论，也不占用「第一次作答」。
- 所有写入按 id 幂等：双击、重试、重复响应都不会重复计分。

内部仍用 BKT（`transit = 0.12`，下限 0.212，低于「挣扎」阈值 0.35——改参数要重新核对，`test/engine.test.js` 有对应测试）来决定验证前是否建议再练一道，但它只在第一次作答、第一次遇到的实例上更新，辅助作答只算一半，**从不授予能力**。

## AI 老师

| 能力 | 做法 |
|---|---|
| 看得见 | 每次请求带上当前任务、屏幕上的数字、同一任务里之前显示过的状态（可以回答「刚才那个为什么变了」）、项目里的代码和报错、这项任务已经给过的帮助。 |
| 接得上 | 追问带上同一任务里的对话记录；换任务时进行中的回答会被停止并注明原因，迟到的回答不会出现在新任务里（AC-10）。 |
| 分级帮助 | 第 1 级指出该看哪里 → 第 2 级提一个思考问题 → 第 3 级对比例子 → 第 4 级部分步骤 → 第 5 级完整解法（需确认，记为辅助完成）。 |
| 少打扰 | 主动开口只有：提交的判断和结果不一致时解释；实验到达关键时刻时一句话；停留很久或来回调参时**邀请**（「我在比较 / 继续自己想 / 需要提示」），从不断言「你卡住了」「你有误解」。后台标签页的时间不算停留。 |
| 可关闭 | 面板顶部「主动提醒」开关随时关掉、随时恢复；关掉后仍可提问，界面上的对错和运行状态照常显示（AC-11）。面板可以收起，对话和任务状态保留。 |
| 验证期间 | 独立验证或项目变式进行中，AI 老师不主动说话；请求帮助或展开讲解会先询问——同意就把这次转为辅助练习（答案保留），之后换新题再验证。验证开着却跑到别的步骤去求助，同样会先问（那里的帮助也可能用在验证上）。 |
| 记在哪次作答上 | 主动求助的回答，记在当前任务和页面上所有开着的题目上（它可能被用在那里）；答错后的解释记在那道题上。宁可多记辅助，不虚报独立。 |
| 反馈就近 | 解释同时出现在题目或实验旁边，每条消息有「查看相关对象」。 |

提醒阈值和间隔在 `src/engine/tutorPolicy.js`，带版本号记在每条帮助记录上。它们是原型沿用的初始值，**没有**经过试点验证是最佳时机。

**五道防线**（`server/`）照旧：结构化输出不依赖 schema；误解 id 只能从作者登记的闭集里选；超长按整句截断而不失败；回答里的每个数字必须能在课程文本或学生屏幕上找到（`factcheck.js`）；学生做题时不在问答和提示里说出答案。新增：简答批改逐条返回评分要点和置信度；不把未经校准的掌握度百分比告诉模型。

## 结课项目（FR-04）

- **运行环境**：`public/pyworker.js` 在 Web Worker 里加载 Pyodide + numpy + pandas + scikit-learn（优先用 `npm run pyodide` 存到本地的副本，没有才用 CDN），加载完即切断网络。学生代码碰不到页面、学习记录和任何密钥（密钥只在服务端）。单次运行上限 30 秒（`?runTimeout=` 可在测试时调短），超时或点「停止」都直接终止 Worker，下次运行自动重启；Worker 崩溃只影响这一次运行。
- **数据包**：`public/project/` 下三个带版本的 CSV（`npm run data` 可按种子逐字节重建），课程里登记了内容哈希，运行时核对。主项目是种子发芽；两个**并行变式**来自另外两个农场，列名、目标列和标签形式都不同，直接重跑主项目的代码过不了。数据里各有一个编号列（当特征就是「行号陷阱」）和一个字符串列（直接喂给树会报真实的错）。
- **记录**：`public/pyruntime/learnai.py` 提供 `log_experiment()`，并在后台记录每次 `train_test_split` 的划分方式、每次 `fit` 用到的数据行，据此检查「验证数据有没有进训练」。每次运行关联代码版本（按哈希存档）、数据版本与哈希、划分与随机种子、运行环境版本。改了代码或参数，旧结果在实验表里标成对应的旧版本；任何一次运行都可以用存档的代码「复现」并比对结果。
- **评分**：五项分开判——代码能完整运行、数据使用合理、实验比较完整（≥3 种设置，含基线和复杂度参数的改变，同一划分）、结论与运行记录一致（结论里引用的数字必须能在记录里找到）、解释成立（AI 按作者的评分要点判；结论完全不提验证集的直接不通过；AI 不可用时这一项「待评定」，可以稍后重新评定，最初的评分和复核都保存）。没有唯一正确参数，也没有准确率及格线。同一份提交只生成一条评分记录。
- **辅助与独立分开**：主项目用过 AI 就记为「辅助完成」；变式的**第一次提交**才算独立验证，没通过或中途求助就换另一个农场的数据（原来那个变式可以继续当练习做）。评分结果里可以展开查看当次提交的代码、目标列、选的模型和结论。
- **超时**：所有 AI 调用在服务端有 60 秒期限（`LEARNAI_MODEL_DEADLINE_MS`），学生停止或离开时上游调用也一并停止；超时显示为「未评定」，可以重试，不计分。

### 运行环境技术验证（初测，作为试点配置记录）

本机（WSL2，无头 Chromium，本地副本的运行环境）实测：

| 项目 | 结果 |
|---|---|
| 冷启动到第一次出结果（加载 Python + numpy + pandas + scikit-learn 并运行） | 约 5.4 秒 |
| 热运行：同一划分上比较 8 种设置 | 约 0.1 秒 |
| 点「停止」到停下 | 约 30 毫秒（直接终止 Worker） |
| 停止或超时后的下一次运行（重启环境） | 约 5 秒 |
| 单次运行上限 | 30 秒（初始设置） |
| 内存 | 受浏览器 WebAssembly 上限约束，未单独设限；试点时需在学生机器上再测 |

从 CDN 加载时冷启动取决于网络，本机实测慢到数分钟，所以试点前应先 `npm run pyodide`。

## 记录、恢复与导出（FR-07）

- 记录存本机 localStorage（`learnai:v2:<课程>`），每次写入的结果都显示在顶栏：写入失败时显示「未保存」，并提供「重试保存」和「下载当前记录」，不会假装保存成功。
- 旧版存档（`adaptive-learn:…`）自动迁移为**历史记录**：做对过的课程题不再要求重做，但旧的「已掌握」不能当作独立验证——相应能力显示为学习中，页面说明要重新验证什么。旧存档原样保留；读不出来的存档会另存备份，不会被覆盖。课程升级时同样说明哪些能恢复、哪些要重新验证。
- 「导出记录」下载一个 JSON 试点包：任务与版本、尝试、评分证据（含逐条评分要点与复核）、行为事件、帮助记录、误解状态、项目的代码存档与运行记录、过程指标（独立验证通过/失败/转为辅助/中途放弃的数量等），并在文件里写明**观测范围**：「平台内没有使用帮助」不等于学生没有用过任何外部帮助。

## 架构

```
src/engine/            与学科无关
  schema.js            课程契约 + 校验（能力、验证任务、评分要点、项目任务包）
  learnerModel.js      尝试 / 评分证据 / 行为事件 / 帮助 / 误解三态；纯函数、幂等
  capabilities.js      能力状态与证据追溯
  policy.js            规则式推荐（每条建议带依据和检验目标）
  persistence.js       存储、写入失败检测、v1 迁移、课程升级说明、试点导出
  tutorPolicy.js       主动提醒阈值与帮助等级（带版本）
  useLearner.js        React 绑定（防抖保存，页面隐藏/关闭时立即写入）

src/courses/decisionTree.js   课程（纯数据）：10 步 + 结课项目任务包
src/labs/              学科相关代码：实验组件、练习/验证题生成器
  tasks.js             任务实例：按内容识别、未见实例选择、校验与备用、重建
src/project/           项目工作区、运行环境封装、评分规则、结果汇总
src/components/        界面：任务栏、验证卡、能力档案、AI 老师面板……

public/pyworker.js           Python 沙箱（Web Worker）
public/pyruntime/learnai.py  实验记录与数据使用检查
public/project/*.csv         带版本的数据包

server/
  index.js             Express：藏 key、SSE 中转、项目解释批改接口
  tutor.js             批改 / 诊断 / 选错提示 / 问答 / 分级提示 / 项目解释批改
  fakeTutor.js         离线替身（LEARNAI_FAKE_LLM=1）
  factcheck.js         数字溯源检查

e2e/                   walkthrough（整门课两遍）、acceptance（AC-01～14）、all（两者）
scripts/make-project-data.mjs   重建数据包
scripts/fetch-pyodide.mjs       把 Python 运行环境存到本地（npm run pyodide）
```

加一门新课 = 一份课程文档 + 它引用的实验组件和题目生成器。采证、能力、推荐、帮助调度都在引擎里，不写学科判断（`test/engine.test.js` 用一门「烤面包」课验证）。

## 测试与验收

- `npm test`：引擎（采证、误解三态、能力、策略、迁移、导出）、任务实例（未见、可复现、不复用、变式确实变化）、项目评分规则、服务端辅助函数、课程与数据包完整性、全部算法数字。`LEARNAI_TEST_PYTHON=<带 scikit-learn 的 python>` 时还会用真实 scikit-learn 跑 `learnai.py` 并接上评分规则。
- `npm run e2e`：真浏览器，
  - `walkthrough`：整门课**全对**一遍、**处处先错**一遍（每步第一次验证故意失败），检查死路、验证题重复或与练习题重叠、题目出现超过两次、请求不带屏幕或任务上下文、控制台错误；`E2E_REAL_LLM=1` 时另查 AI 老师有没有编数字。
  - `acceptance`：逐条验收——

| 编号 | 场景 | 在哪里验 |
|---|---|---|
| AC-01 | 自由调参变差再恢复 | acceptance · AC-01；engine.test |
| AC-02 | 带明确错误理由的判断 | acceptance · AC-02 |
| AC-03 | 答对另一个问题不清除无关误解 | acceptance · AC-03；engine.test |
| AC-04 | 首次全对仍进入未见实例验证 | acceptance · AC-04；walkthrough good；engine.test |
| AC-05 | 看过提示后答对，刷新重答 | acceptance · AC-05；engine.test |
| AC-06 | 曲线题提交前不泄露答案 | acceptance · AC-06 |
| AC-07 | 改代码或参数后运行 | acceptance · 项目 |
| AC-08 | 只有训练分数、没有有效划分 | acceptance · 项目；project.test；pyruntime.test |
| AC-09 | AI 失联、运行超时、评分无效 | acceptance · AC-09 与项目 |
| AC-10 | 请求 AI 后立即切换任务 | acceptance · AC-10 |
| AC-11 | 关闭主动提醒后继续比较 | acceptance · AC-11 |

功能验收通过 ≠ 教学有效：这些测试证明系统按需求运行，不证明学生学得更好（需求文档 §9）。

## 已知限制

- 记录只在本机浏览器，没有账号、不跨设备；老师通过导出文件检查，没有教师后台。
- 没有先跑 `npm run pyodide` 时，结课项目要从 CDN 下载运行环境，离线环境跑不了项目（其余部分可以）。运行时长上限、内存上限是初始设置，需要在试点的运行环境验证中测量后确定（`RUNTIME_LIMITS`）。
- e2e 默认用离线替身，它验证的是流程，不是真实模型的批改质量；批改质量要用固定样例和人工复核检查（需求文档 §10）。
- 提醒阈值、帮助等级的措辞是初始设置，未经试点验证。
- 「树的不稳定」没有验证题生成器，这一步的能力无法标记为已验证。
- 不在本轮范围（P1/M3）：高亮具体树节点/曲线区段的对象级反馈、并排对比两次实验、延迟复测、对照研究、差异明显的第二种任务、课程制作辅助。
