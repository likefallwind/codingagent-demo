# LearnAI

一个自适应学习平台的原型。它与聊天式教学的区别在于三件事：系统维护一个**学习者模型**（知道你哪个概念会、哪里不会、错在哪个具体误解上）、用**确定性规则**决定下一步教什么、并把**可操作的反馈**建立在真实计算之上而非语言模型的判断之上。

现在是一门课，面向学生，目标是用多种动手界面让人真正理解决策树：

| 章节 | 概念 | 数据与算法 |
|---|---|---|
| 主线：一棵树的一生 | 7 步：读树 → 纯度 → 贪心建树 → 深度 → 过拟合 → 剪枝 → 不稳定 | 16 个水果样本 + 同一果园 8 批合成数据；CART（二叉阈值分裂、基尼） |
| 进阶：多值特征的陷阱 | 3 步：熵与信息增益 → 行号陷阱 → 增益率的边界 | 14 天打网球数据；ID3 / C4.5（多路分裂、信息增益、增益率） |

两章的算法族、数据形态、实验组件完全不同，**共用同一套引擎**。进阶章只要求掌握「纯度」那一步就能进入。

每一步都有一个**先预测、再揭晓**的实验：学生先下判断，再由真实计算给出结果。右边的 AI 老师**看得见学生的屏幕**——实验当前显示什么、正在做哪道题、写到一半的答案——并且只在四种情况下主动开口（见下文）。

## 运行

需要 **Node 18 或更高版本**。首次运行会自动安装依赖，不用先跑 `npm install`。

```bash
git clone git@github.com:likefallwind/codingagent-demo.git
cd codingagent-demo
cp .env.example .env              # 填入 MINIMAX_API_KEY
./start.sh
```

然后打开 **http://localhost:5173**。`Ctrl+C` 停止。

### 四种模式

| 命令 | 作用 |
|---|---|
| `./start.sh` | 开发模式。Vite :5173 + API :8787，改代码自动重载。**日常用这个。** |
| `./start.sh prod` | 生产模式。先构建，再由单个进程在 :8787 托管前后端。 |
| `./start.sh test` | 跑单元测试。 |
| `./start.sh e2e` | 在真浏览器里把整门课走两遍（一遍全对、一遍处处先犯错），检查死路、重复出题、AI 老师编数字。需要 API key，约 15 分钟。 |
| `./start.sh stop` | 停掉残留进程（比如上次 Ctrl+C 没清干净）。 |

### API key

AI 批改、提示、问答需要 Minimax 的 key。两种设法，二选一：

```bash
# 写进 .env（推荐，已被 .gitignore 忽略）
echo 'MINIMAX_API_KEY=你的key' > .env

# 或临时导出（优先级高于 .env）
export MINIMAX_API_KEY=你的key
```

**不设也能跑。** 网站、六步实验、所有数学计算和对错判定都在本地完成，完全正常；
只有 AI 那三类功能会返回 502，界面上会明确提示而不是静默失败。

### 换端口

```bash
WEB_PORT=3000 PORT=3001 ./start.sh
```

端口被占时脚本会直接报出占用的进程号并退出，不会静默失败。

### 不用脚本

脚本只是包了一层，底下就是普通的 npm 命令：

```bash
npm install
npm run dev                       # Vite :5173 + API :8787
npm run build && npm run server   # 单进程 :8787
npm test
npm run e2e                       # 需要 MINIMAX_API_KEY；首次需 npx playwright install chromium
```

## 架构

```
src/engine/          与学科无关，不知道自己在教什么
  schema.js          Course 契约 + 校验器
  learnerModel.js    BKT 贝叶斯知识追踪 + localStorage 持久化
  policy.js          教学决策（纯规则，无 LLM）
  useLearner.js      React 绑定

src/courses/         纯数据，等价于 JSON
  decisionTree.js    决策树课程（两章，10 个概念）

src/labs/            唯一与学科相关的代码
  registry.js        widget type -> 组件（labTypes.js 是它的纯数据版）
  screen.js          实验向 AI 老师报告「屏幕上此刻是什么」
  practice.js        练习题生成器注册表（服务端也用，所以不含 React）
  fruitTree/         CART + 水果数据 + 7 个实验 + 练习题生成器
  decisionTree/      ID3 算法 + 打网球数据
  playTennis/        ID3 的 3 个实验 + 练习题生成器

server/
  minimax.js         Minimax 适配器
  tutor.js           批改 / 诊断 / 选错提示 / 问答 / 提示，全部带屏幕上下文
  factcheck.js       数字幻觉拦截
  index.js           Express，藏 API key + SSE 中转

e2e/walkthrough.mjs  真浏览器走查（Playwright）
start.sh             启动脚本（dev / prod / test / e2e / stop）
```

加一门新课 = 写一份 course 文档 + 为它引用的 widget type 写组件（和可选的练习题生成器）。引擎不动。

### AI 老师看得见什么

每个实验通过 `onScreen` 报告一份快照：学生在做什么（一句话）、屏幕上此刻显示的数字、以及可选的「关键时刻」。题目卡报告题干、已排除的选项和写到一半的回答。这些随每次请求发给服务端，于是 AI 老师说的是学生眼前的东西。

快照只含**已经显示出来的**内容。实验还在等学生预测时，答案不进快照——AI 老师不可能泄露它没被告知的东西。学生答错、马上要重试时同理。

### AI 老师什么时候主动开口

全部由确定性规则决定，不由模型决定：

| 情况 | 触发 | 说什么 |
|---|---|---|
| 犯错 | 实验判错、选择题选错、简答题没过 | 立刻调用模型解释为什么 |
| 关键时刻 | 实验报告学生刚到达一个值得一提的状态（如深度拖过最优点） | 一句确定性的话，附「为什么会这样？」按钮 |
| 卡住 | 开始做之后 60 秒没有任何操作 | 问要不要提示 |
| 来回试 | 同一个滑块 20 秒内来回拖了 4 次以上 | 问要不要告诉他该看哪个数字 |

后三种只贴一句话和按钮，不调用模型；学生点了才花一次调用。「我自己先看」让本概念内除犯错之外的主动发言全部闭嘴。两次主动发言之间至少隔 40 秒；关键时刻和来回拖是学生刚做的事引起的，隔 8 秒即可。

### 练习题生成器

每个概念只有两三道作者写的题。以前题做完而掌握度不够时只能重做原题，而重做一道刚看过解析的题测的是记忆不是理解。现在每个概念可以声明 `practice: { type }`，由实验同一套算法按种子生成新题：答案是算出来的，同一种子永远生成同一道题（页面、服务端写提示、e2e 判对错都各自重建），种子由已做过的练习数决定，所以不会重复。

### LLM 用在哪、不用在哪

**用**：批改自由回答、解释已被检测到的错误、选错后给线索、回答学习者提问、给分级提示。

**不用**：
- **不判对错。** 实验室的对错由真实算法瞬时判定。模型只解释"为什么"。
- **不选路径。** 教学决策是规则式的——确定性、可解释、零延迟。
- **不自由发挥数字。** 见下。

### 五道防线

**1. 结构化输出不能依赖 schema。** Minimax 会**静默忽略** `response_format: json_schema`——传了 strict schema 照样返回散文。只能用 `json_object` + prompt 描述 + 去围栏 + 校验 + 重试一次。见 `server/minimax.js`。

**2. 误解 id 必须闭集。** 批改时模型只能从课程作者登记的误解列表里选 id，发明的 id 一律拒绝重试。学习者模型按 id 计数、教学策略按 id 路由，一个编造的 id 比没有更糟。答错但不属于任何登记误解的，判 `incorrect`——实测模型常常看出学生「有个错误信念」却说不出是哪条，连续两次坚持判 misconception，以前会让批改直接失败；现在降级为 `incorrect`。

**3. 超长就截，不要失败。** 模型两次都超出字数上限时，按整句截回上限以内，而不是让学生在犯错之后看到一条报错。

**4. 数字必须可溯源。** 模型被要求"不要编数字"后照编不误——实测它说"训练误差从 3.8% 降到 2.9%"，而真实值是 6.3%。`server/factcheck.js` 机械校验：反馈里出现的每个百分比和小数都必须在课程文本或学生屏幕上出现过，否则拒绝重试；重试仍不过，就删掉带假数字的那几句。问答和提示也一样：服务端先完整生成、校验，再发给浏览器——推理模型本来就是先想完再成段吐字，缓冲几乎不增加等待。

**5. 不替学生说答案。** 学生正在做选择题时，问答和提示里出现正确选项的文字会被拒绝重写。

### 内容准确性

课程文案里引用的每个数字都在 `test/` 里对着真实计算钉死。改了数据或算法，测试会红，文案必须跟着改。

两处刻意的设计：

- **第 1 步的树是作者手画的**（`buildFromSpec`）。因为在这份数据上，算法自己长出的两层树是**完美的**——`无果香` 干净隔出那唯一的苹果，没有任何"混着的叶子"可以用来讲"树不必 100% 正确"。手画的树只定**结构**，所有计数和基尼仍是真算的，UI 也明确标注"示例树 · 非算法生成"。

- **增益率并不能解决多值偏好。** 这是第二门课存在的理由。在 play-tennis 上 Day 的增益率 0.2470 仍高于天气的 0.1564，C4.5 的"高于平均增益再比增益率"启发式同样失效（Day 的增益把平均值抬到了所有真实特征之上）。真正管用的是结构性判断：拒绝在分支几乎全为单例的特征上分裂。

### BKT 参数

`transit` 在答错时也施加，因此掌握度存在**下限**。这个下限必须低于"挣扎"阈值，否则 policy 里"连续答错就换角度重讲"的分支永远不会触发。`transit = 0.25` 时下限是 0.408（高于阈值 0.35，该分支是死代码）；现取 0.12，下限 0.212。改这个参数要重新核对两个数字，`test/engine.test.js` 里有对应测试。

「换角度重讲」会挑一个学生**还没读过**的讲解层（直觉 / 例子 / 形式化）并替他展开。

证据权重：简答 1.0、实验里的判断 1.0、预测 0.8、选择题 0.6、实验里的探索 0.3。探索指「做了某件事」——比如把滑块拖过最优点、扫到了增益最大的那一刀——它说明学生动手了，不说明学生懂了，所以几乎不推动掌握度。

## 已知限制

- 学习者状态存 localStorage，无账号、不跨设备。
- AI 反馈延迟 3–8 秒。问答和提示先完整生成、校验数字后才显示，所以是整段出现而不是逐字流出。
- 布局按 1460px 宽设计，未做移动端适配。
- 「不稳定」那一步没有练习题生成器，题做完而掌握度不够时会重做原题（有三道题，一般用不到）。
- 课程内容目前手写。用 M3 从大纲自动生成 course 文档的管线尚未实现。
